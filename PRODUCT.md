# drymem — product truth

Read before designing or building any surface. The plan is in [PLAN.md](PLAN.md).

## What it is

A team's long-term memory per project, the skills that grow out of it, and the
governance around both. Agents write memory; people read, share and rate it;
tech leads turn what keeps coming up into skills every agent on the project
installs; admins see who did what.

One product that runs anywhere: self-hosted on a laptop with one organisation,
or hosted with many. Same code.

## Who uses it

- **Developers and vibe coders** on a team of any size, using Claude Code,
  OpenCode, Cursor or Codex. They want their agent to remember what the team
  already decided, and to arrive with the team's skills already installed — with
  nothing to run and nothing to remember beyond `git pull`.
- **Tech leads.** They decide which skills a project uses, share memories that
  matter, and review drafts distilled from the team's own work.
- **Admins / compliance.** They invite people, set roles, and need to answer
  "who did what" and "did anyone paste a secret" from one screen.

## Vocabulary

| Word | Means |
|---|---|
| **memory** | A summary an agent wrote at the end of a session. Has a *kind*, a *session*, an author, and a *scope*. Never a transcript. |
| **kind** | decision · architecture · bugfix · discovery · convention · note |
| **shared / private** | A memory is private to its author until they share it with the project. Sharing copies; it never moves. |
| **project** | A repository, identified by its normalised git remote. Two people cloning the same repo land in the same project. |
| **skill** | A folder with a `SKILL.md` and optional files. Platform-neutral. Versioned. |
| **catalogue** | The organisation's set of skills: base, distilled, imported, authored. |
| **enable** | A project chooses a skill from the catalogue, pinned to a version. |
| **lockfile** | `.drymem/skills.lock`, generated by the tool and committed. The enabled set with content hashes. |
| **pull** | Install a project's enabled skills into each platform's own directory on this machine. |
| **distill** | Draft a skill from the memories about a subject. Always a draft; a person publishes it. |
| **audit event** | A record of who did what, when. Includes scrubber hits, never secrets. |

## Principles

1. **Nothing leaves the network it is installed on.** No CDN, no telemetry, no
   third-party host in the shipped UI. A font request is a request.
2. **Summaries, never transcripts.** The agent writes the memory. drymem never
   summarises a conversation itself.
3. **Private by default; sharing is a deliberate act.** And it copies.
4. **A hidden button is not a permission.** Roles are enforced in the service
   layer; the UI hides what you cannot do as a courtesy.
5. **Say what happened.** Every action ends in a message. Every mutating action
   is logged. Silent success is indistinguishable from nothing.
6. **Colour never carries a state alone.** Every state has a word beside it.
7. **Dense for an engineer, legible for a learner.** Tables and chips, plain
   labels, empty states that name the command that would fill them.

## What it is not

- Not a chat log. Not a place to read what someone said to their agent.
- Not another skill registry. skills.sh exists; we import from it.
- Not a tracker integration. No Jira, no GitHub issues feeding the agent.
